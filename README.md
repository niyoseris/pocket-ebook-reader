# Pocket Reader

**An open-source e-ink ebook reader you can carry in a pocket.**

62 × 32 × 13 mm · 2.13&quot; e-paper (250×122) · ESP32-C3 · 1S Li-Po · USB-C
~0.3 s page turn · 28–55 µA deep sleep · **12–24 months** standby on 500 mAh

[Hardware](#hardware) · [Software](#software) · [Quick start](#quick-start) · [Docs](#documentation)

</div>

---

## What it is

A pocket-sized e-ink reader. Its purpose is reading a few pages without taking
your phone out of your pocket: no backlight, no eye strain, and a charge that
lasts for weeks.

Two build tiers, **one firmware**:

| | **Easy build** | **PCB build** |
|---|---|---|
| Time | ~1 hour | ~1 week (incl. PCB order) |
| Tooling | soldering iron, 4 wires | SMD rework (oven/hot air), 3D printer |
| Board | Seeed XIAO ESP32-C3 | ESP32-C3-MINI-1 + TPS63020 + MCP73831 |
| Panel | ready-made e-paper breakout module | bare panel (24-pin FPC) |
| Thickness | ~18 mm (breakout module) | ~13 mm |
| Standby current | ~44 µA (XIAO board) | ~55 µA (TPS63020) / ~28 µA (TPS63900) |
| Firmware | **the same** | **the same** |

The firmware runs **exactly the same** on both pieces of hardware — the pin map
was designed to fit inside the 11 GPIOs the XIAO breaks out.

## Features

**Reading**
- 2.13&quot; e-paper, 250 × 122 pixels, 1-bit (black/white)
- Full Latin-1 + Latin Extended-A glyph coverage including Turkish (the font file is generated)
- Word-wrap with word shifting, paragraph indents, page breaks at chapter starts
- ~7 lines × ~40 characters per page (14 px font), with a 2× magnification option
- Fast page turns with partial refresh; an automatic full refresh every 20 pages
  (clears the e-paper ghosting)

**Usage**
- 3 buttons: previous / next / menu — no touch at all, no frontlight at all
- Menu: font size, refresh frequency, sleep duration, Wi-Fi transfer, delete book
- Deep sleep after 60 seconds of inactivity; with the page button, a return
  **straight to where you were reading** (no boot screen)
- Thanks to RTC memory it keeps which book and which page you are on while asleep

**Book transfer**
- HTTP over Wi-Fi: `http://pocketreader.local`
- Drag-and-drop upload from a browser; plus the `tools/send.py` command-line tool
- On first setup the device opens its own Wi-Fi network (`PocketReader-XXXX`), and
  you enter your home network's password from the browser — no need to recompile
  the firmware
- EPUB → `.epr` converter, entirely with the standard library (no external dependency)

**Power**
- 3.0–4.2 V Li-Po, 500 mA charging over USB-C (MCP73831)
- TPS63020 buck-boost → a true 3.3 V (the screen is powered even if the cell drops to 3.0 V)
- RF completely off outside transfer mode

### Pin map

One map, two boards. The GPIO numbers apply both to the ESP32-C3-MINI-1 and to
the XIAO ESP32-C3.

| Signal | GPIO | XIAO | Direction | Notes |
|---|---|---|---|---|
| `EPD_SCK` | 4 | D2 | output | SPI mode 0 |
| `EPD_MOSI` | 6 | D4 | output | gives up JTAG |
| `EPD_CS` | 7 | D5 | output | active low |
| `EPD_DC` | 10 | D10 | output | 0 = command, 1 = data |
| `EPD_RST` | 8 | D8 | output | strapping pin — a 100k pull-up is required |
| `EPD_BUSY` | 9 | D9 | input | idles HIGH; meets the strapping requirement by itself |
| `BTN_UP` | 3 | D1 | input | RTC domain → wakes from sleep |
| `BTN_DOWN` | 2 | D0 | input | RTC domain → wakes from sleep |
| `BTN_MENU` | 20 | D7 | input | U0RXD — **cannot** wake from sleep |
| `VBAT_ADC` | 5 | D3 | analog | ADC2_CH0, 100k/100k divider |
| USB D− / D+ | 18 / 19 | — | — | USB-Serial-JTAG |

> **Why so constrained?** The XIAO ESP32-C3 header breaks out only 11 GPIOs, and
> of those only GPIO2/3/4/5 are in the RTC domain. All the button/screen/battery
> signals are placed within these 11 pins without violating the boot requirements
> of the strapping pins. Details: [`docs/02-schematic.md`](docs/02-schematic.md)

## Software

```
firmware/                ESP32-C3 embedded software (Arduino C++ / PlatformIO)
  include/config.h         pin map, display rotation, all settings
  src/epd.cpp              SSD1680 driver: init, full/partial refresh, Canvas
  src/epd_lut.h            the vendor's reference LUT tables (source attributed)
  src/font.cpp             .epf binary font loader + UTF-8 decoder
  src/book.cpp             .epr reader + pagination + page-index cache
  src/ui.cpp               screens: library, reader, menu, Wi-Fi, error
  src/buttons.cpp          debounce + short/long press
  src/power.cpp            ADC battery measurement, deep sleep (ext1), RTC state
  src/storage.cpp          LittleFS + NVS settings
  src/wifi_xfer.cpp        HTTP server, upload page, AP setup

tools/                   Host-side tools (Python)
  epub2epr.py              EPUB → .epr converter (stdlib only)
  fontgen.py               TTF/OTF → .epf font generator (Pillow)
  send.py                  upload to the device, list/delete books, Wi-Fi setup
  make_sample_books.py     generates sample books
  gen_placement.py         PCB placement data (the source of all drawings)
  gen_pcb_layout.py        generates the 2D technical drawings (from placement.csv)

site/                    Presentation page opened in a browser
  index.html               3D interactive model + all drawings (single file)

hardware/                Schematic, netlist, PCB drawings, case
  schematic/               schematic, netlist generator, pinout sources
  pcb/                     placement data, 2D technical drawings
  diagrams/                block, wiring, exploded assembly
  enclosure/               parametric OpenSCAD case
```

The firmware has **no third-party dependencies**: the SSD1680 driver, the
`.epf` font loader, the `.epr` book parser and the HTTP server are all
implemented here. The vendored LUT tables in `src/epd_lut.h` come verbatim from
Waveshare's MIT-licensed reference driver, with the source URL recorded in the
file header — they are not invented, because a wrong LUT damages the panel.

See [`firmware/README.md`](firmware/README.md) and [`tools/README.md`](tools/README.md).

### Book format `.epr`

We have our own container format; the reason is simple: the device has 400 KB of
RAM and 4 MB of flash, and parsing EPUB on the device is neither possible nor
necessary. The conversion is done once on the computer, and the device sees only
plain text plus two control bytes.

```
"EPR1" | version | flags | text_offset | text_length | toc_offset | toc_count
title | author | language | encoding | padding
text block:  0x0A = end of paragraph,  0x0B = end of chapter (new page)
table of contents: each entry { uint32 text_pos, uint8 len, title }
```

Full specification: [`docs/06-books-and-fonts.md`](docs/06-books-and-fonts.md)

### Font format `.epf`

There is no font compiled into the device; the font is loaded from LittleFS at
runtime. This way you can change the typeface and size without touching the
firmware.

```
"EPF1" | version | height | ascent | descent | line spacing | glyph count
each glyph: uint32 codepoint | advance | left | width | height | top |
            ceil(width*height/8) bytes, line by line, MSB first
```

## Quick start

### 1. Hardware (easy build, ~1 hour)

Bill of materials and order links: [`docs/01-bill-of-materials.md`](docs/01-bill-of-materials.md)

Wiring diagram: [`hardware/diagrams/breadboard-wiring.svg`](hardware/diagrams/breadboard-wiring.svg)

### 2. Software environment

```bash
# PlatformIO (VS Code extension or command line)
pip install platformio

git clone <this-repo> pocket-eink-reader
cd pocket-eink-reader/firmware
pio run -e xiao -t upload        # easy build
# pio run -e esp32-c3-devkitm-1 -t upload   # PCB build
```

### 3. Generate and upload the font

```bash
cd ../tools
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt

# Generate a font with a TTF that covers Turkish
python3 fontgen.py /usr/share/fonts/truetype/dejavu/DejaVuSans.ttf \
        --size 14 --out ../firmware/data/fonts/reader-14.epf

mkdir -p ../firmware/data/fonts && cp reader-14.epf ../firmware/data/fonts/
cd ../firmware && pio run -t uploadfs
```

### 4. First boot

1. The device boots; if there is no font, a warning screen appears → do step 3.
2. Long-press MENU → Wi-Fi transfer mode. The SSID and IP appear on the screen.
3. Open `http://pocketreader.local` from a phone/computer.
4. Enter your Wi-Fi password once; it will not ask again.
5. Drag and drop your EPUB — the device does not convert, it expects `.epr`.

```bash
# Convert an EPUB and upload it directly
cd tools
python3 epub2epr.py ~/kitap.epub -o /tmp/kitap.epr --title "Book" --author "Author"
python3 send.py /tmp/kitap.epr
```

## Power

Sleep consumption is determined by the **regulator and the battery divider**, not
by the MCU. We made that visible with the breakdown below:

| Item | With TPS63020 | With TPS63900 |
|---|---|---|
| Regulator quiescent current | **25 µA** | **0.075 µA** |
| Battery divider (100k/100k) | 21 µA | 21 µA |
| ESP32-C3 deep sleep | ~5 µA | ~5 µA |
| Feedback divider (1M/180k) | 2.8 µA | 0 µA |
| Panel deep sleep | 1 µA | 1 µA |
| **Total** | **~55 µA** | **~28 µA** |
| Standby on 500 mAh | ~12 months | ~24 months |
| If the divider is made 1M/1M | ~36 µA → ~19 months | ~9 µA → **cell self-discharge dominates** |

What matters while running is not the screen refresh but the **awake time**. The
device stays awake for another 60 seconds after turning a page:

| Usage | Duration (500 mAh cell) | Description |
|---|---|---|
| **Continuous reading** | **~25 hours** | Screen on, ~20 mA |
| Wi-Fi transfer | ~5 hours | Radio on |
| Single page turn | ~170,000 times | 0.3 s × 35 mA — but awake time is ~100× that |

For someone who reads 20 minutes a day this is **~2.5 months** in practice; in
standby, **12 months** (TPS63020) or **24 months** (TPS63900).

> **Why two regulators?** The default BOM uses the TPS63020: its feedback is set
> with two resistors, it is in stock, and its pinout is verified. But it draws
> 25 µA quiescent, and that is half the total sleep consumption. The TPS63900 is
> in the same 2.5 × 2.5 mm WSON-10 package family and draws **330 times less**
> quiescent current; in exchange, its output voltage is selected from a
> configuration-resistor table in the datasheet. Detailed comparison:
> [`docs/07-power.md`](docs/07-power.md)

## Status and honesty

This project is **designed and documented, but has never been physically built
or tested.** Take it as it is:

- **Compiled:** yes. Both hardware targets build in CI
  (`esp32-c3-devkitm-1` and `seeed_xiao_esp32c3`), producing a 915–926 KB
  `firmware.bin`. Getting there took three fixes that only a compiler could
  find — see errors 13–15 in [`CHANGELOG.md`](CHANGELOG.md). All fifteen are
  listed there.
- **Run on hardware:** no. Compiling is not the same as working. Nothing has
  ever been flashed to a real device.
- **Tested:** `cd tools && python3 -m unittest discover -s tests` → **66 tests,
  all passing.** Twelve of them (`.epf` interop) parse the firmware source at
  runtime and assert that both halves of the font format follow the *same* rules;
  that check caught two silent bugs — see [`CHANGELOG.md`](CHANGELOG.md).
- **Verified from official datasheets:** the panel active area and the **24-pin
  FPC pin order**, the panel's external capacitor and boost network, the
  ESP32-C3-MINI-1's 53-pin table, the antenna keep-out area, the strapping
  requirements, the MCP73831 SOT-23-5 pinout and charge formula, the TPS63020's
  14-pin VSON pinout and its 3.3 V `R5`/`R6` values, the TPS63900's 10-pin pinout
  and `CFG` resistors, and the SSD1680's RAM/BUSY/sleep behaviour. All of it in
  [`hardware/schematic/pinouts.md`](hardware/schematic/pinouts.md) with source URLs.
- **Still unverified (13 pins):** the USB-C receptacle pin numbers, the
  USBLC6-2SC6 pinout, the Si1308EDL pinout. `python3 gen_netlist.py --check`
  lists them.
- **BUSY polarity is genuinely ambiguous** in this panel family. The firmware
  makes it a compile-time flag with a hard timeout, so a wrong guess produces a
  clear error instead of a hang.
- **If your screen image comes out upside-down:** change one of the
  `EPD_MIRROR_X` / `EPD_MIRROR_Y` / `EPD_ROTATION` options in
  `firmware/include/config.h`. This setting is deliberately made reachable on a
  single line.
- **Before making your own PCB** run `hardware/schematic/gen_netlist.py --check`;
  it lists the missing pin numbers.
- Six design errors found and fixed during datasheet verification are recorded in
  [`CHANGELOG.md`](CHANGELOG.md) — including a wrong regulator package, a false
  pin-compatibility claim, and a missed external ±15 V boost requirement.
